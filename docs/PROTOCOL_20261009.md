# 财报下一轮评测协议草案（题目 ID 已冻结，质量门槛待审阅）

历史 2026-10-08 的 100 题全库实验保持原样，原始结果是 2 题正确、27 题错误回答、71 题拒答。它的题目多数缺少公司信息，不能与 FinQA 给定报告任务直接比较，也不能因修复评分器而改写历史成绩。任何新运行必须使用新路径，保存代码提交、输入与输出 SHA-256、请求响应、模型版本和实际费用。

## 两种协议与一个代理实验

**A：给定报告数值推理。** 评测调用方提供 FinQA 原条目的报告页面 ID，模型只接收该页的正文、表格和问题，不接收标准答案、程序或金标证据。用已冻结的 200 个 ID 作未参与本项目调试的公开留出集；同一模型、上下文与生成预算下，比较旧提交与修复提交的全集执行准确率、回答覆盖率和错误回答数。A 的报告范围与 FinQA 研究任务接近，但公开测试仍可能出现在预训练中。

**B：完整年报库业务问答。** 输入由用户明确给出公司和报告年份，系统必须先做实体与年份约束，再从完整真实年报检索；答案要有原 PDF 页码、操作数、单位与运算证据。拟定验收至少 200 题、10 份报告、5 家公司、2 个年份，按报告留出，标准答案由独立人员复核；回答内准确率 ≥95%、覆盖率 ≥70%、引用有效率 ≥95%，另有 50 题歧义和不支持挑战集。**这套正式 B 数据及人工复核尚未完成，当前没有 B 质量结果。**

`results/protocol-20261009/` 同时保存 A 的原问题和加上公司、报告年份的 B 代理问题，便于先检查实体约束。代理实验只由官方 FinQA 的 143 个选中页面转录构成，虽覆盖 122 个公司年份组合、72 家公司与 17 个年份，却不是完整原 PDF 报告库，也没有独立复核的业务标准答案；代理成绩不得用于 B 的正式验收。

## 数据边界与重建

官方来源是 `https://raw.githubusercontent.com/czyssrs/FinQA/main/dataset/test.json`，原文件 SHA-256 固定为 `831dbfb2e785dbc227f895ce3f24046433467aec67b09db2bd6ac7692a8a30dc`。筛选先排除已有 dev 40/test 100 的 ID，再排除历史 131 页涉及的整个公司年份报告，从剩余 652 条按 `SHA256(example_id)` 最小顺序取 200 条；已冻结的 ID、查询文件哈希、来源和限制在 `holdout-manifest.json`。正式运行前不能按题目难度、模型结果或标注内容换题；源文件只放忽略的本地 `artifacts/finqa-source/`，不提交原始下载。

`scripts/freeze_holdout.py` 只用 ID、问题文本和来源文件名选题，`scripts/materialize_holdout.py` 在忽略目录分开生成 `documents.json`、A/B 查询和 `labels-scoring-only.json`。预测器只读取文档和对应查询，所有模式预测完成且逐条输出落盘后，评分器才加载标签。官方仓库采用 MIT 许可，但原上市公司年报的再分发权仍需逐份核查；因此正式 B 原 PDF 先保存在本地或受控存储，并用下载及校验脚本复现。

## 评分与失败处理

全集执行准确率是正确数除以冻结题数；覆盖率是有有效数值输出的题数除以冻结题数；回答内准确率是正确数除以有效数值输出数，零回答记未定义且不通过。超时、接口异常、截断、空输出和拒答留在原分母中，单列原因。FinQA 百分比显示值在评分前除以 100，还原 `exe_ans` 的比例单位；比例容差为 `max(0.0005, |gold|×0.001)`，其余数值为 `max(0.01, |gold|×0.001)`。非数值标准答案不事后删除，计为本数值任务不支持并保留在全集分母；支持子集须在正式运行前另列 ID。

每个回答必须记录所选公司和报告年份、检索命中、引文、表格行列、原文值、单位来源、计算计划、拒答原因和模型实际 token 用量。引用有效需支持实体、年份和具体答案，不能只指向报告封面或无关页面；人工或独立复核尚未进行的引用有效率一律记 `pending`。报告两种协议的绝对差、样本数和 95% 区间，配对差用固定 ID 的 bootstrap；置信区间不包含成本与数据集外泛化保证。

## 比较与资源门槛

拟用同一 Qwen3-8B 基座修订 `b968826d9c46dd6066d109eabc6255188de91218`、temperature 0、关闭 thinking、`max_tokens=768`、相同检索语料和上下文预算，对旧提交与修复提交做配对比较。先保留 BM25 基线，再以 dense、hybrid、reranker 在同集上比较最终准确率与成本；oracle 正确证据和给定报告诊断单独命名，不计正式 B 成绩。模型权重、适配器、推理服务和可能的人工复核尚无本轮预算与可核验备份，因此 GPU 模型验收保持 `pending`，不能从 CPU 工程测试推断质量改善。

PRD 中 A 的 ≥60%、B 的 ≥95% 回答内准确率与 ≥70% 覆盖率属于项目拟定门槛，等待用户审阅，不是行业统一标准。门槛或数据协议若要调整，须在正式运行前另存新版本；看到结果后不改本版分母或容差。正式 B 的 PDF 困难页、挑战集、独立答案复核和服务部署另立 manifest 后才可宣称冻结完成。

## CPU 复现命令

以下命令在财报仓库根目录执行，`python` 指向安装了仓库依赖的环境。官方 `test.json` 先放入忽略的 `artifacts/finqa-source/`，下载地址与 SHA 已固定在上文；脚本校验哈希后才写入结果，历史目录不被覆盖。

```sh
python scripts/audit_historical_100.py --output-dir results/audit-20261009
python scripts/freeze_holdout.py --source artifacts/finqa-source/test.json --output-dir results/protocol-20261009
python scripts/materialize_holdout.py --source artifacts/finqa-source/test.json --manifest results/protocol-20261009/holdout-manifest.json --output-dir artifacts/holdout-20261009
python scripts/evaluate_e2e.py --protocol global --documents artifacts/holdout-20261009/documents.json --queries artifacts/holdout-20261009/queries-B-proxy.json --labels artifacts/holdout-20261009/labels-scoring-only.json --output results/protocol-20261009/cpu-rule-proxy-NEW.json
python -m pytest -q
```

最后一条评测命令只跑 CPU 规则代理基线，重新运行时把 `NEW` 换成新的运行 ID；脚本会拒绝覆盖已有结果。GPU 的 A 模型评测使用 `--protocol given_report --url ... --model ...` 并换用 `queries-A.json`，正式 B 需要新的完整 PDF corpus 与人工复核标签；调用任何付费服务前必须另获预算。
